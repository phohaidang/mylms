VIII. Lưu ý cho giảng viên

Vùng nguy hiểm (SV hay sai)

  1. Quên '\0': Khi khai báo mảng ký tự thủ công, SV hay quên thêm '\0' cuối → demo lỗi để SV thấy hậu quả
  2. Dùng == so sánh chuỗi: Lỗi kinh điển nhất. Luôn demo trước: if ("abc" == "abc") có thể true (compiler optimization) nhưng biến chuỗi thì luôn false
  3. gets() vẫn chạy: Một số compiler cũ vẫn cho phép gets() → giải thích tại sao không nên dùng (buffer overflow)
  4. fgets giữ '\n': SV sẽ gặp kết quả lạ khi so sánh chuỗi nhập bằng fgets (vì có '\n' cuối). Chỉ cách xóa: str[strcspn(str, "\n")] = '\0';
  5. strcat/strcpy tràn: Demo lỗi khi mảng đích quá nhỏ → chương trình crash hoặc output lạ

Dự phòng tình huống

Nếu SV hỏi: "Tại sao C không có kiểu string sẵn như Python?" → Trả lời: C là ngôn ngữ "bậc thấp", gần phần cứng. Nó cho lập trình viên toàn quyền kiểm soát bộ nhớ. Python xây kiểu string bên trên bằng cách tự động quản lý '\0', kích thước mảng. C để các em tự làm → hiểu sâu hơn bản chất máy tính.

Nếu SV hỏi: "Em dùng strcpy nhưng bị warning 'unsafe'" → Trả lời: Visual Studio gợi ý dùng strcpy_s (phiên bản an toàn của Microsoft). Trong môn này, dùng strcpy là đủ. Thêm #pragma warning(disable : 4996) ở đầu file nếu dùng VS.
